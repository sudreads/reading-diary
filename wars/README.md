# Food Wars / Beer Wars 🍺🍔

קרב חברים: מי אוכל, שותה וחוגג יותר. כל נקודה מחייבת תמונה, והתמונות נאספות לגלריה של הקבוצה.

## איך משחקים

1. **מקימים או מצטרפים** - הבוס מקים משחק, בוחר על מה מתחרים (בירה, מים, אוכל, ים, מסיבות, נופים, או אתגר משלו) ומקבל קוד בן 6 תווים.
2. **רשימת המתנה** - מי שמצטרף עם הקוד מחכה עד שהבוס מכניס אותו לקבוצה.
3. **הבוס מתחיל** - עם או בלי שעון עצר (שעה עד שבוע).
4. **לוחצים ומצלמים** - עשית משהו? לוחצים על הכפתור ומעלים תמונה. בלי תמונה אין נקודה.
5. **הסוף** - פודיום, אלוף לכל קטגוריה, טבלה מלאה והגלריה של כולם.
6. **משחק חוזר** - הבוס פותח סיבוב נוסף עם אותם אתגרים, ומי שהיה בקבוצה נכנס ישר, בלי קוד ובלי רשימת המתנה.

הטבלה והגלריה מתעדכנות בזמן אמת. הבוס יכול למחוק תמונה חשודה, להוציא שחקן ולהכניס מאחרים באמצע המשחק.

## הרצה

צריך Node 20 ומעלה. אין תלויות להתקין.

```sh
cd wars
npm start            # http://localhost:8787
```

| משתנה | ברירת מחדל | מה זה |
| --- | --- | --- |
| `PORT` | `8787` | הפורט של השרת |
| `DATA_DIR` | `./data` | המשחקים (JSON) והתמונות. צריך דיסק שנשמר בין הפעלות |
| `TRUST_PROXY` | `0` | כמה פרוקסי משלכם עומדים לפני השרת. באירוח מנוהל (Render, Fly, Railway) זה בדרך כלל `1` |
| `MAX_STORAGE_MB` | `5120` | תקרה לכל התמונות יחד. כשהיא מתמלאת העלאות נדחות |

כדי שחברים יצטרפו מהטלפון השרת צריך כתובת ציבורית עם HTTPS ודיסק קבוע ל-`DATA_DIR`.

### הדרך הקצרה: Render

1. נכנסים ל-render.com ומתחברים עם GitHub.
2. New > Blueprint, בוחרים את המאגר ואת הענף, ובשדה Blueprint path כותבים `wars/render.yaml`.
3. מאשרים. מקבלים כתובת `https://food-wars-XXXX.onrender.com` ושולחים אותה לחברים.

הקובץ `render.yaml` מגדיר שירות אחד, דיסק של 1GB לתמונות ואת משתני הסביבה. דיסק קבוע דורש תוכנית בתשלום;
בלי דיסק כל המשחקים והתמונות נמחקים בכל הפעלה מחדש.

אחרי העלייה כדאי להציץ בלוג: השרת מדפיס פעם אחת כמה כתובות יש ב-`X-Forwarded-For`, וכך אפשר לוודא ש-`TRUST_PROXY` מתאים.

### כל אירוח אחר (Fly.io, Railway, VPS)

```sh
docker build -t food-wars wars
docker run -p 8787:8787 -v foodwars-data:/data -e TRUST_PROXY=1 food-wars
```

השרת הוא תהליך אחד ששומר מצב בזיכרון ובקבצים, אז מריצים עותק אחד בלבד.

## אבטחה

לפני שעולים לאוויר:

- **HTTPS בלבד.** השרת עצמו מדבר HTTP, אז חייב לעמוד מאחורי פרוקסי שמסיים TLS (כל האירוחים המנוהלים עושים את זה).
- **להגדיר `TRUST_PROXY`.** בלי זה כל המבקרים נספרים ככתובת אחת ומגבלות הקצב יחסמו את כולם יחד. עם ערך גבוה מדי תוקף יכול לזייף כתובת ולעקוף אותן.
- **עותק אחד, דיסק קבוע**, ורצוי גיבוי של `DATA_DIR`.

מה כבר בנוי פנימה:

| איום | הגנה |
| --- | --- |
| התחזות לשחקן אחר | לכל שחקן טוקן אקראי של 192 ביט. בשרת נשמר רק ה-hash שלו, והוא נשלח רק בכותרת `Authorization`, אף פעם לא ב-URL |
| פעולות של בוס בידי מי שאינו בוס | כל פעולת ניהול נבדקת בשרת מול הטוקן. הלקוח לא מחליט כלום |
| ניחוש קודי משחק | מיליארד קודים אפשריים, נעילה אחרי 15 ניחושים שגויים ב-10 דקות, ומי שכן מנחש רק מגיע לרשימת ההמתנה |
| הצפה (משחקים, הצטרפויות, בקשות, חיבורים) | מגבלות קצב לכל כתובת, תקרות לכל משחק ולשרת כולו, תקרת אחסון |
| העלאת קובץ זדוני | רק JPEG/PNG/WebP לפי תוכן הקובץ, עד 2MB, שם קובץ אקראי, מוגש עם `nosniff` ו-CSP חוסם |
| XSS | הלקוח לא משתמש ב-`innerHTML` בכלל, ו-CSP מחמיר: בלי סקריפטים חיצוניים או inline |
| CSRF ו-clickjacking | אין עוגיות, נבדקים `Origin` ו-`Sec-Fetch-Site`, והדף לא נטען בתוך iframe |
| התחזות בשם | שמות ייחודיים בתוך משחק, תווים בלתי נראים ותווי היפוך כיוון מוסרים |
| צפייה בתמונות בלי אישור | כל תמונה נטענת עם הטוקן של השחקן ורק לחברי הקבוצה. קישור שהועתק לא פותח כלום, וגם מי שהוצא מאבד גישה |

## בדיקות

```sh
npm test             # ה-API: הרשאות, רשימת המתנה, תמונות, ניקוד, ותרחישי תקיפה
npm run test:e2e     # משחק שלם עם חמישה "טלפונים" בדפדפן אמיתי, כולל ניסיון XSS (דורש Playwright)
```

## מה נשמר

- שם שבחרת, והתמונות שהעלית. אין חשבונות, אין סיסמאות, אין מעקב.
- התמונות מוקטנות בטלפון לפני ההעלאה, ונתוני המיקום (EXIF) נמחקים מהן.
- תמונות נגישות רק לחברי הקבוצה. אין קישור ציבורי לתמונה.
- משחק נמחק מהשרת, עם כל התמונות שלו, 30 יום אחרי שנגמר.
- משחק שאף אחד לא התחיל נמחק אחרי שבוע, ומשחק שאף אחד לא סיים מסתיים לבד אחרי שבועיים.
